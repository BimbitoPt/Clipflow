# Clipflow desktop

Windows desktop application built with Tauri 2. The installed app embeds the React editor and a Windows FFmpeg binary. It does not need a Vite server, Node.js, Cargo, or an independently installed encoder to run. Windows WebView2 is required; the installer bootstraps the runtime when absent.

## Use

- **Import media** opens the Windows file picker and assigns an image or video to the selected scene. Imported media is copied into Clipflow's local application data first.
- **Save project** writes a `.clipflow` JSON manifest and a sibling `<project name>.assets` directory. Keep both together when moving a project. Saving copies imported media into that directory; the original source can then be moved without breaking the saved project.
- **Open project** restores the idea, brand profile, saved base script and edits, caption labels/style, visual effects, voice setting and selected media. The manifest also records scene timing, its measured/estimated provenance, motion intent, resolved captions and the renderer revision. Double-clicking `.clipflow` files works after installation. Ctrl+O, Ctrl+S and Ctrl+N open, save and create projects.
- **Export** opens a native MP4 destination picker. Frames are generated by the same Canvas renderer as the preview and streamed to native FFmpeg. Voice, if enabled, is generated locally with the existing SpeechT5 pipeline. Its first use requires a model download.
- **Cancel export** terminates the encoder and removes its temporary files. During voice preparation, cancellation takes effect when the current synthesis operation returns. A completed export can be previewed in the app or revealed in Explorer.

The supplied `desktop-projects/Signal House GT3 RS.clipflow` demonstrates the corrected short labels and one continuous source of GT3 RS footage. Keep its adjacent assets directory when copying it.

## Development and packaging

Prerequisites: current Node.js/npm, Rust MSVC toolchain, Visual Studio C++ build tools, Windows SDK and WebView2.

```powershell
npm install
npm run desktop:dev
npm run desktop:build
```

`scripts/prepare-desktop.mjs` copies the Windows binary supplied by `ffmpeg-static` into bundle resources. The release executable is `src-tauri/target/release/clipflow-desktop.exe`; the NSIS setup file is under `src-tauri/target/release/bundle/nsis/`. Use the installer for normal use, because the executable needs its bundled resource files beside it when run directly.

## Implementation boundaries

- `src/lib/desktop.ts`: versioned project contract and native bridge.
- `src/components/DesktopToolbar.tsx`: project operations in the editor.
- `src/lib/desktop-render.ts`: exact-frame native export adapter.
- `src-tauri/src/projects.rs`: native dialogs, media copying, project persistence and asset access.
- `src-tauri/src/render.rs`: FFmpeg process lifetime, audio input, frame streaming, cancellation and final file commit.

The previous Rust CLI has a separate script/caption renderer. Desktop uses shared browser frame plans to avoid silently regenerating scripts or changing motion/captions. Its FFmpeg service is deliberately separate from the CLI's ONNX dependencies.

## First-release limits

This is a Windows prototype. Exports run one at a time while the editor is locked. Frame streaming prioritizes preview/export agreement over speed. There is no Remotion batch adapter, background queue, timeline audio mixing, cloud sync, automatic updater or code signing yet. Voice model downloads require a connection; silent exports use local assets only. MOV and WebM playback depends on the codecs supported by WebView2; MP4/H.264 is the most portable import format.

Architecture and dialog references: [Tauri architecture](https://v2.tauri.app/concept/architecture/) and [native dialog plugin](https://v2.tauri.app/plugin/dialog/).
